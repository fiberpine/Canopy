# V14：固定20ms观测，动态MTP执行

## 为什么保留这一版

选定step277317，实际训练commit `c43c72f9e8fbe1c9402560ed6ca33f85572dc2a8`。它是修复时钟/IPC后、有完整训练和冻结证据的可审计候选，并非跨轮绝对性能冠军。V08旧结果存在时钟遗漏与IPC风险，不能静默升级接口后沿用旧得分；其他路线详见统一探索记录。

## 动作、观测与训练

- 72维状态：原70维20ms历史，加实际经过时间及上一计划周期两个特征。
- 窗口头保持原动作定义；执行端整数百分比约为`int(100 * 4**a_cwnd)`，实际窗口由native映射与底层CUBIC共同演进。
- 时间头归一化输出`a_mtp∈[-1,1]`，映射`MTP = 20 * 8**((a_mtp+1)/2)`ms，范围20—160ms。
- **观测仍固定20ms。** 长MTP期间继续读取遥测、计算状态/效用；到决策边界才执行新的RL窗口动作，不重复乘窗口倍率。此版不能作为“动态观测周期省唤醒”实现。
- `joint_mtp.py`累积区间奖励，成本0.02每次决策扣一次；折扣按真实持续时间计算。20ms也是物理经验更新额度的时间单位；不能把完整critic更新当环境步。
- 原Orca效用、target moving BN一致性、均衡采样及每20ms已入库真实经验0.08次完整critic更新规则保留。一次完整critic迭代有两个optimizer操作。
- 从包内`models/prior-v13`的独立fixed80窗口/critic先验微调，重新建立优化器/replay/计数/TCP。不是从零，也不是无缝resume。正式模板保留5000critic校准及真实周期覆盖后开放学习的门槛；smoke有显式降低门槛。

主要源码在`frameworks/mtp20`；重点为`joint_mtp.py`、`staged_timing.py`、`trainable_timing.py`、`connection_reset.py`、`distributed.py`和native `code/runtime/src/orca-server-joint-mtp.cc`。

## 原训练和不足

24actor涵盖8锚点、8浅队列动态、4观测噪声、4NYC蜂窝角色，通过180秒重连轮换环境。277317有效transition；124259完整critic更新/248518critic操作、119259actor、124259target。原1800秒计划因继承timeout提前停止，实际1433.98—1451.81秒/actor；不能称完成原预算。新通用入口已给物理预算留足墙钟余量，原部分结果仍如实保留。

92次冻结评测中，完整24条件单次60秒主评测的trim10利用率93.02%—99.98%。四个浅队列R20动态条件MTP标准差小于5ms，其中两个约99%靠上界，**不满足双动作必要门槛，研究结论PARTIAL**。强制40/80ms能在部分高RTT条件把同权重利用率降到约2%—3%，而独立训练fixed80约97%—99%；这说明周期/窗口耦合，不能说80ms周期本身无效。

该轮缺相同覆盖的新fixed80训练强对照；不能凭高吞吐宣布动态调度收益。V14与V31场景和观测语义不同，不用跨轮总均值排“冠军”。下面完整保留24条件主结果，不只挑好场景。

## 运行

```sh
runtime/venv/bin/python run.py evaluate --variant mtp20 --scenario 0 --seconds 60
runtime/venv/bin/python run.py verify-training --variant mtp20
runtime/venv/bin/python run.py smoke-training --variant mtp20 --actors 1 --seconds 90
runtime/venv/bin/python run.py train --variant mtp20 --actors 24 --seconds-per-actor 1800 --cluster configs/my-cluster.json
```

选定模型在`models/mtp20/model.*`，评测关闭探索/优化；训练与评测模板分别在`templates/mtp20-train.json`、`templates/mtp20-eval.json`。完整历史数值/动作健康/失败证据见`evidence/mtp20`。本次真实短训练只验证可用性，不修饰原研究成绩。
