# 探索累积效应与端主机在途上限：诊断、修复与下一次检查（2026-10-27）

数据：fiberpine/Canopy commit a969f67（`evidence/scalar-ipc-init-20261027`）和既有`evidence/baseline`冻结评测。本文没有新的TCP运行，结论均可从仓库内证据复算。代码改动见第4、5节，尚未推送。

## 0 结论

1. **小初始化的残余爆窗来自iid乘性探索的累计冲量。** GPT的分解已经给出：到首次百万窗口，探索冲量+8.66/+8.30，确定性项−0.46/−0.39，整数取整−2.44/−2.19（ln单位，G48/G72-R200 seed4）。探索在log cwnd上是随机游走。
2. **新发现：这两个条件处在端主机在途上限之上。** 8次独立运行的在途量都钉在约2075包（3.12 MB线上字节）：不同容量、不同队列（2BDP/5BDP）、不同策略（随机初始化/已训练），丢包均为0，cwnd都在INT_MAX。窗口不再约束发送，没有任何反馈把cwnd拉回，漂移会一直积分。
3. **窗口动作定义自带约−0.5%/命令的向下偏置。** 来源是`int(100·4^a)`截断和native整数乘法。这与GPT分解的取整项一致（−0.0071~−0.0079/步）。中性策略需要π≈+0.0035才不漂移。这一项不改，但要记录，两臂相同。
4. **修复（只改探索方式）：** `zero_sum_offset`。单步扰动方差与原Gaussian 0.2相同，但累计扰动有界，不再是随机游走。代码和测试已完成。
5. **下一次零优化检查：** 共20次正式运行加2次smoke，单机，约1小时。预测和判定规则在运行前登记，并配有自动判定脚本。
6. **端主机上限（M2）单独作为环境变量检查，放在探索检查之后。** 这是所有方法共同的评测环境问题：baseline 5BDP网格有8/24个条件受影响。

## 1 M1：iid探索在乘性动作下是随机游走

执行动作把窗口乘以4^a，所以探索对ln cwnd的贡献是所有扰动之和：iid σ=0.2时，标准差为0.2·ln4·√t。

- 60秒共3000步，标准差约15（ln）。
- 只有丢包（CUBIC降窗、PRR）能把窗口拉回。
- 窗口受约束的条件（R20、G12-R200、G24-R100）不会出现百万窗口，但会反复越过缓冲：a969f67小初始化丢包率9–26%。
- 窗口不受约束的条件没有任何回拉力，见第2节。

GPT的分解（`small-failure-decomposition.json`）：

| run | 动作数 | 总ln增长 | 命令 | 命令间native | 确定性 | 探索 | 取整 |
|---|---|---|---|---|---|---|---|
| G72-R200 s4 | 308 | 10.93 | 5.72 | 5.21 | −0.39 | +8.30 | −2.19 |
| G48-R200 s4 | 309 | 11.56 | 5.75 | 5.81 | −0.46 | +8.66 | −2.44 |

把探索项换成有界偏移（|o|≤约0.6 ln），同一时段的命令项约为−2.6/−2.9，不再是+5.7。剩下的native增长受慢启动条件限制：cwnd须小于2·max_packets_out，而max_packets_out又受第2节的上限约束。按这个静态反事实，窗口达不到1e6，也达不到4×(BDP+queue)。状态变化会改变π，所以仍需实测。

## 2 M2：端主机在途上限约2075包

在途量估计 = 出发速率×基础RTT + 容量×平均排队（trim10）：

| 证据 | 条件 | cwnd | 在途 | 丢包 | 排队 |
|---|---|---|---|---|---|
| a969f67 upstream s3 | G48-R200-q2 | INT_MAX | 3.119 MB = 2074包 | 0 | 320.0 ms |
| a969f67 upstream s3 | G72-R200-q2 | INT_MAX | 3.122 MB = 2076包 | 0 | 146.8 ms |
| baseline screen-trained r1–r3 | G48-R200（5BDP） | 均值INT_MAX | 3.120–3.121 MB = 2075包 | 0 | 320.1 ms |
| baseline screen-trained r1–r3 | G72-R200（5BDP） | 均值INT_MAX | 3.122–3.123 MB = 2076–2077包 | 0 | 146.9 ms |
| a969f67 小初始化 s4 | G48 / G72-R200-q2 | 3.7e7 / 5.2e7 | 2.98 / 3.03 MB（含前期爬升） | 0 | 299 / 139 ms |

这些运行的容量不同（48/72 Mbps），队列不同（2BDP/5BDP），策略不同（随机/已训练），在途上限却相同，都没有丢包。如果只有cwnd限制，INT_MAX的窗口必然会溢出droptail队列。所以存在一个与算法无关的端主机上限。

**上限来自哪个缓冲：**
- 发送缓冲：上游Orca和Canopy的`setup.sh`把`tcp_wmem`最大值设为4 MiB。若每个1448字节段的truesize约为2024字节，可容纳约2072段，与观测几乎一致。
- 接收窗口：默认`tcp_rmem`最大值6 MiB，`adv_win_scale=1`，窗口约3 MiB，即约2172段，比观测高约4.5%。
- 两者需要一次`ss -tmi`快照区分（已加入检查）。修法相同：两个上限一起调大。

**后果：**
- 超过上限后，窗口动作对吞吐、延迟、丢包都没有影响，奖励对动作是平的。critic在这些状态学不到方向，actor也得不到纠正。
- 同一个已训练模型（step-2412694），在冻结评测中没有探索噪声：
  - 在G48/G72-R200，确定性动作均值为+0.38/+0.76，即每20 ms×1.7/×2.9，cwnd全程INT_MAX；
  - 在没有触到上限的G24/G42-R200，均值为−0.046/−0.052，排队13–24 ms，表现正常。
  - 越过上限后进入一个吸收区：动作已无效，策略输出也变成强正。所以这不只是探索的问题，学到的策略同样会被困住。
- G48-R200的320 ms排队由端主机缓冲决定，不是策略选择的结果。
- 这直接违反"两个动作必须具有有效作用"：窗口不约束时，任何窗口动作都无效。

## 3 动作定义的量化偏置

- 百分比用`int(100·4^a)`截断，native再算`percent·cwnd/100`并向下取整。
- 有探索噪声时，截断误差约均匀分布，平均每条命令约−0.5%（ln −0.005）；cwnd较小时，整数下取整还会再加一项。
- 自测的抖动量化器为−0.0052/步；GPT实测的取整项为−0.0071~−0.0079/步。
- 中性点：π·ln4 = 0.005，即π*≈+0.0035。
- 无噪声时：π∈[0, 0.0072)执行100%（保持）；π∈[−0.0072, 0)执行99%，即每20 ms −1%。

**对双动作设计的含义（以后用）：** 偏置是按每条命令计的。20 ms时约−22%/秒，160 ms时约−3%/秒。MTP改变决策频率，也就改变了窗口的系统性漂移。双动作分析须报告或扣除这一项，否则MTP的"效果"可能部分来自量化器。

## 4 修复：zero_sum_offset探索

**定义：**
- 目标偏移 o_t = ρ·o_{t−1} + √(1−ρ²)·σ_o·z_t；
- 执行 a_t = clip(π_t + o_t − C_{t−1})；
- 累计 C_t = C_{t−1} + (a_t − π_t)。

**性质：**
- 不发生clip时C_t = o_t：窗口相对确定性轨迹的偏离是平稳的4^{o_t}，不是随机游走。
- ρ=0、σ_o=σ/√2时，单步执行扰动o_t − o_{t−1}的方差正好是σ²=0.04，与原iid相同。两臂只差"累计"这一个性质。
- 每次调用从同一个NumPy全局流取一个标准正态，与上游`G_Noise`的`randn(1)`序列逐值相同（已测）。同seed的两臂因此使用同一串随机数，是配对比较。
- 每条TCP连接重置一次。

**实现与测试：**
- 实现：`frameworks/canopy_single/scalar_exploration.py`。
- 接入：`distributed.py`。`exploration_process`缺省为`iid`，旧路径逐字不变；replay中存的仍是实际执行的动作。
- 测试：`tools/test_scalar_exploration.py`共8项，包括单步std≈0.2、累计std≈0.141且有界、clip后能恢复、同随机流、连接重置。

**已知限制：**
- ρ=0时偏移每步刷新。R200下一个RTT有10步，窗口偏移对奖励的影响在RTT尺度上会部分平均掉。训练时探索信号可能偏弱，尤其长RTT。
- 这是以后训练要观察的现象。ρ>0（持续偏移）只作为以后的单独变量，本次不改。

**与文献的关系：**
- 有色噪声探索（Eberhard et al., ICLR 2023的粉红噪声；Hollenstein et al., TMLR 2022的动作噪声比较）研究的是动作噪声的时间相关性。
- 对积分型执行器，应在被积分的量上平稳，即动作噪声取平稳过程的差分。DDPG的OU噪声方向正相反：在乘性窗口上它会让游走更快。
