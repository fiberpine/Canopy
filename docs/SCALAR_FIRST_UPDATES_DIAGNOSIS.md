# L1首批更新失稳：机制分析与离线复现方案（2026-10-27）

数据：fiberpine/Canopy commit 5ca361b（`evidence/scalar-limited-learning-20261027`）。本文只做只读分析，加一个NumPy等价模拟，没有新的TCP或TF运行。新增工具见第5节，均未推送。

## 0 结论

1. **失败发生在学习更新本身，与探索、IPC、初始化和双动作无关。** GPT的判断成立：累计探索峰值只有0.575，IPC 147,584帧逐一一致。
2. **速度：这个actor在Adam下，只要critic的动作梯度保持同一符号，就以固定速度冲向饱和，与梯度大小无关。**
   - 我按同样的层、TF1默认初始化、小输出头和moving统计actor损失写了NumPy等价实现，dQ/da固定为0.02、−0.02或0.001。
   - 约45次更新到|π|≥0.5，约75次到0.9，与实测"约64–70次更新时π≈+1"一致。
   - BN冻结时速度几乎不变（69–74次）；预先校准BN反而更快（26–27次）。所以BN统计不是速度来源，单独校准BN也修不好。
3. **方向不是继承自初始critic，而是在最初几十次critic更新里产生的。**
   - 随机初始critic在24个actor的探针状态上，dQ1/da有88–100%为负（均值−0.03~−0.05），在线策略却冲向+1。
   - 我的推测：动作会立刻改变下一状态里的pacing/max_bw和samples/cwnd；早期critic的目标来自随机target网络。于是critic学到的∂Q/∂a约等于γ×（随机target对这些特征的敏感度）×（特征对动作的响应），符号由初始化决定。
   - 这一点要靠离线复现检验。
4. **为什么一点偏置就是灾难。**
   - 乘性动作每20 ms执行一次：π=0.0072是每步+1%，即每秒+64%；π=0.05是每秒×32。
   - 未训练策略几乎没有状态依赖，初始π只在−0.035~0.17之间，偏置得不到状态反馈抵消。
5. **根本原因是违反双时间尺度。**
   - actor约75次更新就能穿越整个动作范围；target网络的时间常数是1/τ=1000次更新。actor比critic最慢的部分快约13倍。
   - TD3推迟策略更新，正是为了让价值估计先稳定。
   - MuJoCo类任务里，动作直接进入即时奖励（如控制成本），critic的动作梯度几百次更新内就有依据。这里动作对奖励的影响至少要过一个RTT、还要经过内核，最初上千次更新里critic的动作梯度主要是随机target的副产物。
6. **开闸时的更新欠额不是触发原因。**
   - 欠额约1,515次，执行速度约185次/秒；即使按稳态100次/秒，也会在约0.65秒内到同一位置。
   - 但停止后的排空发生在只多了爆窗数据的静态replay上，又把策略推到了−1。
7. **下一步：同意先做零TCP离线复现。**
   - 我写了可直接运行的`first_updates_replay.py`（TF1、只读），含R0–R5六组和预测（第5节）。
   - 若结果如预测，下一次在线验证只改"actor放行与速度"一个变量：critic-only 3,000次（=3/τ，期间更新BN统计），然后actor学习率1e-6。这样actor穿越时间约1万次更新，是target时间常数的10倍以上。
   - 若critic落地后梯度符号已不一致、actor不再冲，则只加放行门即可。

| 事件 | 数值 |
|---|---|
| 覆盖门打开、第一次更新 | 入库27,436（warmup 12,288），欠额(27,436−12,288)×0.1≈1,515次 |
| 第一次迭代耗时 | 268 ms（图预热），之后每次约4–5 ms |

## 2 速度：Adam对梯度大小不敏感

`tools/scalar_learning_check/actor_speed_sim.py`（NumPy，seed 3/4/5）：

| 设置 | 到\|π\|≥0.5 | 到\|π\|≥0.9 |
|---|---|---|
| moving BN更新（同L1），dQ/da=+0.02 | 48/48/44 | 78/76/73 |
| 同上，dQ/da=−0.02 | 46/45/48 | 74/74/77 |
| 同上，dQ/da=+0.001 | 51/50/46 | 81/79/76 |
| BN冻结在初值 | 46/46/42 | 74/72/69 |
| BN预先校准后更新 | 16/16/15 | 27/27/26 |
| actor学习率1e-5 | 352/333/323 | 868/768/969 |

偏置达到危险水平还要更早。|π|≥0.05对应窗口每秒×32：
- lr 1e-4：9次更新到0.05，16次到0.1；
- lr 1e-5：93次和157次；
- lr 1e-6：545次和896次，4,000次内到不了0.5。

原因：Adam的每步更新约等于学习率×m̂/√v̂。梯度方向稳定时m̂/√v̂≈1，每个参数每步移动约一个学习率，与梯度大小无关（Kingma & Ba 2015）。这个actor有256个隐单元，输出层的预激活每步可移动约1e-4×Σ|h|，即0.01量级。

## 3 方向：不是来自初始critic

- **初始critic（step 0）：** 24个actor的探针上，dQ1/da均值都为负（−0.029~−0.055），正值比例0–12%。
- **在线：** 64–70次更新内，所有actor的确定性输出到+1。按第2节，这要求最初约60次更新里，actor看到的dQ/da几乎一直为正。所以critic的动作梯度在头几次更新就翻了号。
- **可能来源：**
  - 即时奖励几乎不依赖当步动作；
  - 但动作会立刻改变下一状态的pacing/max_bw（内核按cwnd重算pacing）和samples/cwnd；
  - target网络初始是随机的，它对这些特征的敏感度，经过TD目标传给critic的∂Q/∂a。
- **预测：** 换一组critic初始化，冲的方向会变；初始target对第64、66维输入的敏感度符号，能预测冲的方向。
- **排空期：** replay里新增的是爆窗数据（大窗、高丢包），critic学到"大动作不好"，actor以同样速度冲向−1。

## 4 双时间尺度

| 量 | 值 |
|---|---|
| actor穿越时间（lr 1e-4，方向稳定） | 约75次更新 |
| target网络时间常数（τ=0.001） | 1,000次更新 |
| critic学习率 / actor学习率 | 1e-3 / 1e-4（在Adam下两者都以约一个学习率每步移动） |

- **原则：** 双时间尺度actor-critic要求actor是慢过程（Konda & Tsitsiklis 2003；Borkar 1997）。TD3的延迟策略更新是同一思想的工程版（Fujimoto et al. 2018）。
- **数量要求：** actor穿越时间T_a至少是target时间常数T_c的10倍，约1万次更新。按第2节的缩放，这对应actor学习率约1e-6，或1e-5配合每10次critic更新一次actor。
- **最初阶段还需要放行门：** 在target换代（约3/τ=3,000次）之前，critic的动作梯度没有依据，此时actor一步都不该走。

## 5 离线复现：`tools/scalar_learning_check/runtime/first_updates_replay.py`

**做法：**
- 用与`tf_postmortem.py`相同的方式重建learner图，恢复step 0。
- replay只取第一次更新前的27,436条（按birth）。
- 每次迭代执行与`distributed.py`相同的操作：critic、actor+BN更新、target。
- 只读，不写checkpoint，约1–2分钟。

**记录内容：** 固定384个探针状态上：
- 策略：π均值、饱和、按RTT分组；
- critic：dQ1/da与dQ2/da（均值、正值比例、双critic同号比例、按RTT分组），Q；
- 训练：batch critic损失、actor梯度范数；
- target：target critic对第64维（pacing）和第66维（samples/cwnd）的敏感度。

| 组 | 设置 | 预测 |
|---|---|---|
| R0 | 原样，采样seed 3/4/5，300次 | 60–100次内\|π\|≥0.9，与在线一致 |
| R1 | critic与critic2重抽初始化（target复制），3次 | 冲的方向随抽样改变；初始target对第64/66维的敏感度能预测方向 |
| R2 | 不更新actor BN统计 | 速度与R0相差不超过15% |
| R3 | critic-only 3,000次（BN统计照常更新），再按1e-4放行 | 放行时双critic同号比例>0.8，dQ/da按RTT有结构；放行后仍在约100次内\|Δπ\|≥0.5（方向多半为负）。若成立，说明只加门不够 |
| R4 | actor学习率1e-5 | 比R0慢约7–12倍 |
| R5 | critic-only 3,000次，然后actor学习率1e-6 | 放行后1,000次内\|Δπ\|≤0.1 |

**判定：**
- R0复现，R2速度不变：确认机制，BN排除为主因。
- R3放行后仍冲：下一次在线验证的唯一变量为"actor放行与速度"（R5的设置）。
- R3放行后不冲（\|Δπ\|<0.1）：唯一变量只用放行门，学习率保持1e-4。
- R0不复现：说明在线replay在前64次更新中新增的数据起了作用，需按birth逐步加入replay重做。

**局限：**
- replay是静态的，没有策略改变后的闭环数据；
- 采样序列与在线不同；
- critic重抽每组只抽一次。

## 6 下一次在线验证（离线结果确认后再登记）
