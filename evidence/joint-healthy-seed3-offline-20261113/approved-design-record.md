## 3. 动作、状态和迁移

**动作：**输出 `(a_cwnd, a_mtp)`。窗口保持原 `4**a_cwnd` 倍率及 native 整数执行语义；MTP 保持 20—160 ms 对数映射 `20 * 8**((a_mtp+1)/2)`。时间分支用 softsign，避免 tanh 过早精确饱和，但不声称 softsign 能杜绝边界集中。

窗口倍率在每次决策只施加一次；等待期间 CUBIC 按 ACK 正常演化。不会把窗口倍率重复写入，也不默认乘上 `MTP/20` 作为频率补偿。同一倍率每 20 ms 与每 160 ms 执行并不等效，这正是联合学习需要解决的耦合。

**首版状态：**保留原 70 维前缀，加实际上一间隔、上一计划 MTP、10 帧实际时间间隔，共 82 维。新增窗口输入权重零扩展。这样只保证在**相同原 70 维输入**上原窗口函数不变，不保证新计量、空 RTT 帧或变周期历史的分布相同。82 维是最小实验起点，不宣称充分 Markov 状态。

无新 RTT 样本的间隔保留 sample count=0 和真实 dt，绝不把旧 SRTT 标成新测量。记录按条件分层的空样本比例、最后新 RTT 的年龄上下界。若退步集中在这类状态，先验证只补充明确的 freshness/age 特征；不直接搬入全部 149 维。所有状态布局、单位、历史顺序和计量模式有独立 schema 标记，禁止只按张量形状加载旧模型。

**模型：**窗口分支迁移当前 actor 权重与 moving BN；时间分支使用独立的小型网络，无 BN，避免时间梯度在冻结阶段修改窗口共享层。两个分支的动作交给同一组联合 Q 网络学习。旧 critic 最多作为近似初始化；新增状态/时间动作输入零扩展，其准确性由真实新数据校准，不能靠复制就宣布兼容。

新建 Adam、replay、计数和连接；targets 从迁移后的 online 网络硬复制，包括 moving statistics。冻结窗口阶段同时禁止窗口参数、BN 更新和任何通过 Q/target 路径产生的写入。联合阶段再开放两个动作的训练，检查双方确有梯度和参数/输出变化。固定窗口教师只训练 MTP 不作为最终双动作成果。

时间头原始 logit 预置为有限值对应 40 ms；固定 20 ms 诊断时显式屏蔽它。20 ms 是 softsign 映射端点，不能用无穷 logit 初始化并假装可正常学习。开放时间动作前必须已有相关周期覆盖，不能从未校准的 40 ms 行为突然全面开始。

## 4. 奖励与性质约束分开处理

保留原 Orca 效用函数形状，不接入 `raw-sym`、`heu`、性质分数或 QC。变周期必须改时间账本，否则“每次决策给一次原 reward”会改变物理时间上的目标。

令 `h=0.02s`、`gamma=.995`、`dt` 为真实观测边界间隔，使用：

```
D = gamma ** (dt/h)
R = u_interval * (1-D)/(1-gamma) - lambda_call
y = R + D * (1-terminal) * min(Q1_target, Q2_target)
```

该 R 是把区间效用视作常数时的折扣累计近似；不是精确重建未观测 RTT 尖峰。20 ms、lambda=0 时恢复单步效用；不把计划 MTP 冒充实际 dt。一次调用成本只扣一次，不能按每个 20 ms 子槽再重复扣。

**分两步：**首轮机制/迁移/漏测检查 `lambda_call=0`。它不能证明系统开销目标已学到。机制通过后，正式收益实验再与零成本组配对比较少量非零调用成本；系数在实验登记时固定，不盲用历史 .02，也不将其说成实测 CPU 换算。调用成本是资源目标，与 Canopy 性质约束不同；本方案请用户批准保留这个可选配置，默认仍为 0。

### 必须先审计的两条奖励偏差

1. baseline 延迟因子使用内核 SRTT；新模式只在边界观测，无法由单点或区间均值重建 P95/P99。改成平均 RTT 也不能自动消除问题，若调整则单独登记。
2. observed-peak `max_bw` 是历史观察峰值，不是容量。对 `bytes_acked/dt` 做长区间平均可能降低观察峰值，产生与实际利用率不一致的奖励收益。不能据 reward 上升宣布创新。

先检查本地已有细粒度记录是否足够，在同一固定 20 ms 轨迹上按 20/40/80/160 ms 离线聚合，量化效用/峰值/P95 漏测差异。仅有短摘要时明确不足，未来另做短冻结采样，不为了分析自动开机。离线聚合只能判断同轨迹下计量偏差，不能推断改变控制频率后的真实性能。

仅在“累计满160ms”时更新 max_bw 仍会跨网格，不能声称与周期无关。若必须修正归一化，需要独立提出可部署、无容量 oracle、无隐藏 20 ms 读取的定义，并重新验证固定 20 ms 对照；不在移植阶段暗中更改。

G1/G2 的固定 20 ms 性能门采用事前写明的配对容差，不能要求随机 TCP 流逐包完全相同。特别地，`scheduled_feedback_publishable` 在初始化后允许没有新 RTT 样本的有效快照，已不同于旧等待新 RTT 的循环。若冻结策略失配，先定位空样本/计量原因，再决定是否需要显式迁移训练。

校准不能只靠“已做5000步”宣布完成：需每条件×周期有保留经验、周期分桶的未参与优化样本、TD/短回报尺度检查以及 actor/BN 冻结逐项证明。校准阈值和物理时间/更新上限在未来短实验前登记；没有真实数据时不虚构已通过。解除冻结时保留每统计一次写入，并把解除后固定20ms评测设为回归门。

新创新及其独立训练 fixed 对照都采用**相同自然 CUBIC 启动**；若正式训练采用 180s 重连，则各组相同，并清空该连接 history/max_bw 等局部状态，明确 terminal/truncation 规则，禁止把两个连接拼成转移。短冻结准入不重连。这是新的微调协议，不能称历史 legacy 训练原配方复跑。

## 6. 公平训练账本

保留 1 learner＋24 actor；不在本阶段扩集群。新经验实际入库后，按 `0.1 * 新增真实物理秒 / .02` 发放完整 critic 更新额度，沿用当前基座 .1，而不是历史双动作 .08。扣除/起算 warmup 的具体账本保持所有对照一致；不能靠无新经验的墙钟增长额度。

同时记完整 critic 迭代、两次 critic 优化器操作、actor/target 次数，不能混为“更新步”。保留每 actor 平衡采样，记录周期分布及物理覆盖；少量周期覆盖采样仅服务校准，不能把 synthetic padding 当真实经验，也不重复按 dt 放大奖励。主要比较用相同物理暴露和完整更新预算；相同每转移更新数仅作后续敏感性对照，不宣称两种预算能同时恒等。

## 7. 验收及收益声明

先测当前冻结基座在计划动态/浅缓冲条件的弱项；这些尚未因静态健康获得保证。静态训练与验证/动态留出分开登记；新增种子是“给定当前预训练基座后的微调种子”，不冒充重新获得多个独立健康底座。

首批独立训练强对照至少三个 fixed MTP，例如20/80/160ms，和联合组使用同一迁移起点、观测定义、启动、训练数据及物理预算。必要时补40/120ms。**同权重强制改周期是因果诊断，不能替代独立训练 fixed。**旧 V31/旧 fixed 权重可作历史参考，不充当本轮匹配对照。

建议预先冻结的静态工程目标（尚未执行，不是已有结果）：

- 条件等权利用率相对同轮基座下降不超过1个百分点，各条件均值不低于95%。
- 平均排队及条件 P95 均值相对同轮参照增加不超过20%；逐条件/P99/丢包全部列出，不用平均数掩盖灾难格。基座零丢包的静态组要求保持零丢包。
- 相对20ms基座，策略/观测调用率至少下降50%，实测推理＋native进程 CPU 秒/流秒至少下降10%；只少调用不算省CPU成功。

这些是**建议批准的目标**。正式实验应同轮配对至少三重复，不以历史99.7453%替代当前参照，也不在看到结果后放宽阈值。动态/浅缓冲条件另设事前吞吐/尾延迟门，不要求所有动态拥塞场景零丢包。

CPU 主口径：同主机、同核数/绑核、单流冻结推理下，Python/推理进程＋native 的 CPU 秒/物理流秒；另报包括 Mahimahi 的完整 run、整机 CPU/软中断、读 socket/唤醒/调用率。统一日志级别，排除其他训练，区分启动/full/trim10。重复测量报告波动，开销曲线至少有三个独立 fixed 点；只在实测CPU相近（建议差≤5%或测量区间可比）时声称相近预算比较，不用两点任意插值制造收益。

不要求联合策略在调用率上支配160ms等所有常数周期。研究目标是在性能—实测开销前沿取得可复核改善，尤其在动态留出条件上证明自适应的作用。如果它始终选择160ms且不优于匹配 fixed160，只能报告工程节流结果，不能说学到了有益的自适应调度。

## 8. Canopy 性质如何将来扩为双动作

当前只形成设计，**首版不实现性质奖励或 verifier**。未来先做冻结模型离线 shadow 检查，证明定义合理、与实测退化有关，再单独做性质加入/关闭消融。

|性质方向|建议双动作定义|能声称的范围|
|---|---|---|
|窗口方向/活性|沿用按拥塞/损失状态限制执行后cwnd方向的思想；把过去k步换成真实毫秒窗口；依据native实际整数倍率和TCP窗口|给定状态集合下动作约束，不等于未来吞吐保证|
|时间响应|检查 `(a_cwnd,T)` 联合区域，例如持续拥塞且尚无纠正动作时，不允许激进增窗同时长时间不再观测|候选设计性质；前提须实测验证，不照搬成“高排队一律短MTP”|
|噪声鲁棒性|对同一可行输入扰动集合，同时限制执行窗口变化和log-MTP变化，并保留两输出关联|仅所声明扰动集合和输出包络的性质；需单独审计编码、量化与BN|
|时限活性|在物理时限内出现合适动作/再次观测；显式处理RTT年龄、未返回ACK及CUBIC持续演化|只有采样日志检查时是经验性质；要证明闭环时限还需环境可达性模型|

实现注意：原性质代码使用 `state[-2]` 取 invRTT、把 action 当标量。扩展状态/动作后不能原样调用；必须用显式 schema 选当前 invRTT、窗口列及时间列。symbolic 输出改为二维还需验证 softsign、指数映射和整数窗映射的可靠包络。独立输出上下界可构成保守盒子，但一般会丢失相关性；不能只检验两个头各自有界就宣称 TCP 闭环安全。

“高排队⇒缩短MTP”过强：已经减窗、飞行中的包尚未反馈时，立即再推理未必有帮助。窗口方向、响应期限、时间动作应联合判断。性质分数若以后接奖励，还要定义物理时间权重，避免改变决策频率就改变性质奖励密度；决策点证书也不能冒充整个未观测间隔内状态安全的证明。
