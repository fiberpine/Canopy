# 与 Claude 的执行共识

2026-11-10。原研究会话仍在生成详细复盘时，另请 Claude 进行简短独立复核，以避免五机空等。Claude 赞成优先用五机已成功过的固定 20 ms、单窗口 Orca 风格配方，随机 seed 3 运行完整 240 万条。它要求固定终点 checkpoint、六格筛查与 24 格比较口径，保留物理预算和工程／数值硬故障处理，性能波动只记录。浅缓冲单列，预留磁盘和日志容量。当前方案已按这些条件登记。

正式训练采用原 70 维 raw 奖励配方。仅调整阶段预算、日志/检查点频率及协调器把历史性能守卫和持续更新欠额改成告警。原生执行、模型、奖励、动作、探索、训练条件、采样和更新额度复用归档。终点评测只选择排空已获更新后的最终 checkpoint。前置烟测独立运行，权重和回放隔离。

原研究会话随后也确认优先用历史配方随机起跑、完整运行 240 万条、性能守卫只记录。它指出历史六格平均排队的固定阈值会把归档正控也筛掉，排队应只有上界，并要用今天同条件的归档模型作比较。现登记使用同期逐格正控筛查、排队只有上界，并对可疑格做配对重复。详细回复另建议所有条件预先双重复和事后筛选中间 checkpoint，预算最多三小时。本轮采用 95 分钟预算、终点主判和定向补测，依据用户要求减少开支；中间 checkpoint 用于观察和取证。
